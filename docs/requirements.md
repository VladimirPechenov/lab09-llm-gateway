# Сверка с опубликованным заданием ЛР9

Источник: https://github.com/kolesnikov-vstu-gameai/lab09-llm-gateway, ветка Master.
Исходный шаблон сохранён в истории до step-1. Студент: Печенов В. В., ИВТ-465.
Пользователь подтвердил, что других вводных, методических указаний и титульного листа нет.

| Требование | Реализация / доказательство |
|---|---|
| FastAPI, auth | /v1/chat, X-API-Key; tests/test_gateway.py, demo.json |
| Rate limit в Redis | Lua token bucket, TIME, TTL; конкурентный тест, 31-й запрос = 429 |
| Routing | длина >200 или маркеры сложности, две модели |
| Cache в Redis | SHA-256 структурированного ключа, TTL, hit/miss в /health |
| Moderation вход/выход | Unicode NFKC, блок-лист, безопасная замена, не кешируется |
| Retry, timeout, fallback | ограниченное число попыток, временные ошибки, резервная модель и static |
| Логирование | JSON: id, status, latency, npc, model, cached; без ключа/текста |
| Нагрузочный тест | Locust: 50 пользователей, 300 с на режим, 30% общих запросов |
| latency, throughput, cache hit | results/benchmark.json, CSV, /metrics, график |
| Docker Compose | gateway + Redis с healthcheck; optional Prometheus |
| Разрешённая заглушка с задержкой | LLM_PROVIDER=mock, MOCK_DELAY_S=0.15; явно указано |
| Коммиты step-1, step-2… | git log и история GitHub |
| Видео на Диске / YouTube | ссылка README, MP4 исключён .gitignore |
| v1.0 + Release | GitHub Releases |
| Отчёт 5–7 страниц, разделы 1–7 | docs/report.pdf, report.md, диаграмма и график |

Ограничение оформления: опубликованный черновик требует официальный титульный лист кафедры,
но его нет в доступных материалах. Отчёт оформлен по доступной структуре на 6 страницах.
Соответствие неизвестному официальному шаблону не заявляется.

Нагрузочный пример из README преподавателя трактуется как образец протокола, а не целевые числа.
Все опубликованные показатели получены собственным запуском. Интеграция платного LLM не заявляется
как проверенная в реальном аккаунте; SDK OpenAI проверен локальным HTTP transport.
Модель-заглушка не генерирует произвольный текст и не оценивает качество LLM.

Неверный API-ключ одного провайдера не исправляется заменой модели того же провайдера.
В этом случае конечный fallback-static сохраняет игровой диалог и отмечает degraded=true.
Успех резервной модели проверен при внедрённом отказе основной модели.
